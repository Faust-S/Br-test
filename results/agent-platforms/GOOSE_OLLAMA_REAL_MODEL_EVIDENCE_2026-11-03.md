# Goose 1.55.0 + настоящая Ollama: проверка инструментального задания

**Дата:** 2026-11-03. Исполнитель Goose 1.55.0. Локальные CPU модели `qwen2.5:0.5b` и `qwen2.5:1.5b`. Runner Ubuntu 24.04. Никаких API-ключей, приватных исходников и удалённого inference. Одна попытка на конфигурацию, **не статистика надёжности**.

## Принципиально раздельные критерии

- L0: Goose запускается и получает ответ реальной LLM — подтверждено.
- L1: модель создаёт любой файл по открытому заданию — не доказательство чтения источника.
- L2: модель вызывает чтение источника, получает фактический toolResponse — требуется анализ журнала, не достаточно текстового заявления.
- L3: модель вычисляет правильное значение, вызывает `write`, а независимая проверка читает точный полученный файл — **критерий завершённого сквозного задания**.
- L4: IWXA Task/Result/Review, модель и пользовательская среда переживают перезапуск — в этом публичном исследовании не проверялось.

## Методическая коррекция

Первоначальный PASS на 0.5b был ложноположительным **относительно цели сквозного задания**. Тест обновлён: результат больше не раскрывается в prompt; требуется реальный `shell` request и соответствующий успешный `toolResponse` с фактическим содержимым, а также `write` и независимое чтение точного файла. Прежний первоначальный машинный результат сохраняется, но не интерпретируется как прохождение нового критерия.

## Решение для IWXA

1. Не рекомендовать `Goose + qwen2.5:0.5b` или `Goose + qwen2.5:1.5b` как уже доказанное решение многошаговой файловой задачи. Наличие возможностей CLI/Tool calling не достаточно.
2. Не переносить вывод «Goose не работает» на более сильные модели; пока это измеренная граница этих двух точных связок и данной задачи.
3. В будущем выборе исполнителя различать `model_available`, `tool_available`, `tool_call_succeeded`, `final_artifact_verified` и `Task_Result_persisted`.
4. У действующего приватного `GooseLocalCliAdapter` Agent 0.2 используется режим `GOOSE_MODE=chat` и запрет реальных инструментов, поэтому даже независимый L3 PASS не означал бы готового I4 в Personal Agent.
5. Выбор более ресурсоёмкой модели оправдан только после сопоставления пользы, задержек, аппаратных требований и фактических пользовательских задач. Не создавать новый общий исполнительный механизм ради проведения исследования.
