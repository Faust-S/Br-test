## Проверяемый исходник и реальный дефект

Взята ТОЧНАЯ копия реального публичного `browser-lab/benchmarks/compare_frames.py`, Git blob `8ea7a15e874b6ae5c169bdb4a31d4e6e16229c55`, и неизменённый существующий тестовый модуль Git blob `a4a17e6fe84a37b989425e6f96965b2896530e5f`. Копия находится во временном Git-проекте, исходный файл браузерной ветки не изменялся.

Модуль оценивает индекс `int(.95 * count)`, что даёт неверный nearest-rank p95 на точных границах. Новые независимые регрессии для N=20 и N=40 выявляют дефект: ожидаются значения 100 и 80, а фактически 200 и 120. До работы Aider: 4 прежних теста PASS, 2 новых FAIL.

## Почему проблема существенна для IWXA

Статус `CLI exit 0` недостаточен. `Applied edit` недостаточен. Даже `git diff not empty` недостаточен. Правильная квалификация кода требует `test baseline FAIL → real source diff → unchanged tests → independent post-edit tests PASS`.

Для того же Aider 0.86.0 / Qwen2.5-Coder 3B ранее был **действительно успешный** короткий пример с расчётом скидки: [41679890756](https://github.com/Faust-S/Br-test/actions/runs/41679890756), 7/7 регрессий PASS после точной правки. Разные результаты **не противоречат друг другу**: это разные реальные по сложности задачи.

Вопрос для выбора программы: модель, задача, размер контекста, формат редактирования, реальные тесты и аппаратная цена. Ни один single-case PASS не делает программу универсально готовой; два FAIL не делают все версии Aider или более сильные модели непригодными.

## Конкретное решение, без бесконечного перебора

- Остановить серию `Qwen2.5-Coder 3B × screenshot p95` после двух режимов. Исследовательская гипотеза «diff устранит ограничение whole» опровергнута на этом случае.
- На уровне IWXA **не** объявлять эту точную связку надёжным исправителем существующих более длинных модулей.
- Для маленьких локальных программных задач Aider остаётся кандидатом — имеется один подтверждённый PASS и один подтверждённый FAIL для более длинного файла; не ставить в статус общей I4-интеграции.
- Следующий эксперимент оправдан только при конкретном пользовательском кодовом проекте с работающими тестами и разумно более сильной моделью / сопоставимой альтернативой; сначала использовать существующий `AgentRuntimePort`, не создавать второй Core.

**Правильная формула для обнаруженного дефекта:** `errors[min(count - 1, max(0, math.ceil(.95 * count) - 1))]` либо эквивалентная корректная nearest-rank реализация. Это исследовательский reference, а не коммит браузерного продукта. Изменения браузера не вносились.
