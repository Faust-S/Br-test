# Нативная интеграция браузерной панели в Tauri-приложение

Статус: публичный стенд W067, не интеграция в закрытый продукт. Оригинальный Google MCP 1.14.0, WebView2 Evergreen, Tauri 2.12.7. Не добавлять Electron, новый движок, новый ToolRuntime, новый реестр инструментов или хранилище браузерных результатов.

## Нативный хост
- Использовать один native Window и его основную WebviewWindow/обычный Webview плюс гостевой Webview. Создавать нативный child на UI-потоке.
- В Tauri после появления второго Webview `Window::is_webview_window()` становится false. `Manager::get_webview_window` и IPC command arg `WebviewWindow` не подходят для многокомпонентного главного окна. Для команд основной оболочки использовать `Webview` (идентичность вызывающей страницы, URL, навигация), для операций над HWND использовать её `window()`/тип `Window`. Отдельные обычные одно-WebView окна могут остаться WebviewWindow.
- Привязать capability к label доверенной оболочки и проверенному origin/path, а не выдавать полномочия всем дочерним WebView одного Window. Правую поверхность скрывать при закрытии вкладки, смене рабочей области, переключении на другой материал и модальном перекрытии; не рассчитывать, что HTML z-index перекроет нативный child.
- Передавать текущую прямоугольную область из существующей правой панели. Преобразовывать CSS-координаты в физические по реальному client rect и viewport; учитывать DPR/zoom/resize. Не использовать фиксированную ширину, скринкаст или iframe.
- Явный путь основного профиля можно сохранить, но нельзя оставлять глобальный WEBVIEW2_USER_DATA_FOLDER, который будет применяться и к гостю. Два явных data_directory, вне каталога установки. В производственной интеграции проверить сохранность старого профиля, установленный EXE и отсутствие executable-adjacent cache. CDP открыт только для специально выделенного браузерного профиля; loopback endpoint не является полной локальной авторизацией.

Оригинальные API: https://github.com/tauri-apps/tauri/blob/tauri-v2.12.7/crates/tauri/src/window/mod.rs , https://github.com/tauri-apps/tauri/blob/tauri-v2.12.7/crates/tauri/src/webview/webview_window.rs , https://github.com/tauri-apps/tauri/blob/tauri-v2.12.7/crates/tauri/src/lib.rs .

## Оригинальный MCP и общий инструментарий Agent
- Запускать только закреплённый оригинальный пакет с npm integrity, без отдельного скачивания Chromium. Использовать уже имеющийся Node.js runtime или штатный маршрут установки зависимостей, если он доступен.
- Подключение к guest через штатный autoConnect и каталог EBWebView. Сначала проверять точную идентичность страницы и отсутствие основного интерфейса в доступных CDP targets. Для пользователя не нужен отдельный браузерный процесс Electron.
- Использовать общий MCP-инструментарий Agent, его существующую регистрацию и политики. При отсутствии stdio расширить существующий transport (официальным совместимым SDK либо минимальной адаптацией транспорта), сохранив discovery, tool digests, права, receipts и lifecycle. Тестовый JSON-RPC драйвер qualify.py не является production MCP-клиентом.
- Схемы брать из original tools/list, не создавать вторые описания. Артефакт original-mcp-catalog.json и mcp_negotiations сохраняет реальный контракт сервера. Сначала выдавать необходимый набор наблюдения, навигации, форм и действий; пакетные формы через fill_form экономят число вызовов. Не выдавать весь диагностический каталог автоматически.
- Встраивание вкладок принадлежит native host: new_page/close_page из Google MCP не считать нативным открытием/закрытием вкладки без специальной проверки. Каждая операция pageId связывается с конкретной разрешённой видимой вкладкой. При переключении пользователя или рабочей области не переиспользовать устаревшие идентификаторы.
- Для файлов пользоваться существующими разрешениями Workspace и ограниченными корнями MCP. Не включать allow-unrestricted-paths, не копировать cookie в модель, не отправлять произвольные файлы. При потере ответа на внешнюю операцию не повторять её автоматически: повторно наблюдать страницу и существующий результат через штатные механизмы.
- Выключить необязательную телеметрию. Настоящие сайты, авторизация и локальный endpoint на пользовательском устройстве требуют собственной квалификации; локальные fixture-тесты не подтверждают доступ ко всем сервисам.

Оригинал Google: https://github.com/ChromeDevTools/chrome-devtools-mcp/tree/chrome-devtools-mcp-v1.14.0 . Microsoft: https://learn.microsoft.com/en-us/microsoft-edge/web-platform/devtools-mcp-server .

## W067.5: переносимый stdio-транспорт

В `stdio_transport.py` вынесена постоянная JSON-RPC stdio-сессия из уже прошедшего браузерного стенда. Это только транспорт, без второго каталога, политики, Task/Result, собственного браузера или дополнительных Python-зависимостей. Ввод argv задаёт доверенный хост. Базовая поддержка initialize 2025-11-25, notifications/initialized, запросы tools/list и tools/call, ping, уведомления списка, лимиты сообщений, последовательность запросов, остановка и отсутствие автоматического повторного вызова после неопределённого результата. Код не претендует на поддержку всех расширений MCP. Оригинальные ответы, включая isError, сохраняются без подмены. В общем адаптере Agent использовать фактически согласованную версию, discovery через initialize для stdio, общий механизм каталога/digest и его существующую классификацию операций. Ошибку tools/call isError не считать ACK; при возможном уже совершённом действии сохранять UNKNOWN. Интеграция только в Br-test; настоящий общий адаптер Agent ещё не изменён.

## W067.7: динамические вкладки

Нативный хост назначает монотонный индекс, открывает новый child с environment действующей вкладки и закрывает выбранный child через Tauri. Закрытие последней вкладки запрещено; при закрытии активной выбирается предыдущая, либо следующая. Новый bootstrap /tab-new/<index> предназначен только для квалификационного стенда; после подтверждения original get_tab_id можно перейти на нужный URL. События URL несут индекс вкладки, команды адресной строки проверяют актуальность выбранного индекса. В публичном стенде лимит 12 одновременно открытых вкладок. Это не нормативное ограничение Agent. Открытие ссылки target=_blank остаётся отдельной задачей: не отдавать её в new_page без подтверждения нативного child. Для production не выпускать действия AI по вкладке до подтверждения привязки, а операции close/create координировать с активными Task через общий ToolProvider.
