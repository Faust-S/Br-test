# IWXA Universal Install — передача в новый чат (04.11.2026)

## Задача и ограничения

Разработать **общий повторно используемый модуль установки программ**, не отдельные установщики. Открытый репозиторий `Faust-S/Br-test`, ветка `work/2026-11-03-universal-install-module`. Закрытый Agent 0.3 подключит его как компонент на следующем этапе, но **пока не изменяется**. Графический IWXA Browser — прекращённый продукт; не возобновлять. Obscura Worker — первый проверенный устанавливаемый пакет; jq 1.8.1 — второй независимый контроль универсальности.

## Текущая работа: универсальный Managed Artifact

- `universal-install/iwxa_universal_install/manifest.py`: `ManagedArtifactSpec`; data-only, pinned SHA, platform, program_id, slug, имя бинарника, формат однофайлового архива.
- `universal-install/iwxa_universal_install/preparer.py`: общий подготовитель ZIP/tar.gz с HTTPS-прокси, строгими хешами и очисткой временных файлов.
- `universal-install/iwxa_universal_install/managed.py`: общие операции `prepare / apply / inspect / verify / recover / remove`, без вшитой логики конкретного продукта.
- `universal-install/iwxa_universal_install/obscura.py`: адаптер совместимости `ObscuraManagedBackend`, наследуется от общего backend; специфичный `ArtifactSpec` и старый подготовитель Obscura остаются.
- `universal-install/qualification/independent_jq.py`: второй независимый реальный продукт, официальный jq 1.8.1, публично опубликованные SHA-256, установка из локально запакованного однофайлового архива, запуск и удаление без jq-backend.
- `universal-install/tests/test_managed_backend.py`: два независимых data-only манифеста, установка, повторное чтение, удаление, отрицательные сценарии.
- `.github/workflows/universal-install-independent-jq.yml`: реальные jq-прогоны на 5 GitHub-hosted конфигурациях (официального Windows ARM64 в выбранном upstream-релизе нет).

**Важно:** рефакторинг ещё требует независимой полной приёмки. Нельзя выдавать новый generic backend за PASS, пока не получены фактические отчёты Actions. Проверить старые Obscura regression/native/network workflow на новой ветке и SHA, исправлять дефекты общего кода, не плодить отдельные обработчики программ.

## Непременные критерии

1. Добавление новой обычной однофайловой ZIP/tar.gz-программы: **только манифест**, ни одной правки generic-библиотеки.
2. Сохранить публичный контракт Obscura и исходные отрицательные тесты.
3. Реально установить, запустить, повторно прочитать и удалить независимый jq 1.8.1 на Windows x64, Linux x64/ARM64, macOS x64/ARM64.
4. Программа другой архитектуры не устанавливается. Контроль хешей — до и после установки. Подмена манифеста, посторонние файлы и повреждённое обновление отклоняются без потери соседних версий.
5. Сохранить явное решение хозяина установки/удаления, существующие квитанции у хозяина, не создавать Store/registry/permission manager.
6. Завершить CI-regression/real-native перед передачей к Agent 0.3; итоговый HEAD/TREE записать в новый чат и ссылками на конкретные запусковые журналы.

## Не охватываем этим срезом

Многокомпонентные программы, MSI/EXE-установщики, PKG, WinGet/Goose, сложные post-install hooks, работа в пользовательских профилях и интеграция приватного Agent. Для них потребуются отдельные уже переиспользуемые backend-плагины, а не модификации общего `ManagedArtifactBackend`.

## Дальнейший маршрут

1. Свежие HEAD/TREE и `AGENTS.md`, если появится.
2. Проверка Python-контракта и все тесты `universal-install/tests` на GitHub-hosted ОС.
3. Исправить выявленные ошибки в generic-коде.
4. Проверить отдельно Obscura через старый API и jq через data-only API.

6. Только после отдельного указания — интегрировать общий компонент в закрытый Agent 0.3.
