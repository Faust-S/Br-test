# IWXA — универсальные установочные backend (открытый компонент)

**PCB 0.1.0-dev.1, source-only.** Разработка в публичном `Faust-S/Br-test`. Первым устанавливаемым пакетом служит **доработанный IWXA Obscura Worker**. Разработка графического IWXA Browser прекращена: этот компонент **не устанавливает и не тестирует IWXA Browser**.

Модуль предназначен для встраивания в разные продукты, включая закрытый IWXA Personal Agent 0.3. **Исходники Agent сюда не копируются.** Устанавливаемые пакеты и потребители модуля — разные сущности. Это общий backend, а не отдельное приложение, менеджер программ, реестр, Core, Store, система разрешений или Setup.

## Публичный контракт

`iwxa_universal_install.ProgramInstallBackend`: `inspect`, `prepare`, `apply`, `verify`, `recover`. Реализован первый вариант `ObscuraManagedBackend` (`IWXA_MANAGED_ARTIFACT_V1`). Он использует существующий `iwxa_obscura.preparer` для строго закреплённых архивов Obscura. WinGet и pinned Goose пока остаются действующими backend внутри приватного Agent; их перенос **не объявлен выполненным**.

Ответственность приложения-хозяина: выбор программы и каталога, план и его digest, подлинное пользовательское согласие, запись `STARTED` до `apply`, сериализация операций, итоговая квитанция, подключение к провайдеру и выполнение. `ApprovedInstall` — переданный хозяином параметр, **не самостоятельное доказательство согласия**. Модуль не хранит квитанций и не делает сетевых обращений без явного вызова `prepare(..., archive_path=None)`.

Маршрут: `ArtifactSpec` с закреплёнными digest → `prepare(archive)` = `STAGED_NOT_ACTIVATED` → хост подтверждает действие и выдаёт `ApprovedInstall` → `apply` публикует ровно один проверенный бинарник в новый versioned directory → `verify` читает SHA-256 с диска и возвращает `INSTALLED_NOT_CONNECTED` → подключение и запуск решает продукт. `recover` — только чтение, **никогда** повторная установка.

## Тесты

В корне `Br-test`:

```sh
python -m unittest discover -s universal-install/tests -v
python -m unittest discover -s agent-headless/tests -v
```

Публичный Actions workflow проверяет это на Windows и Linux в выделенных ephemeral runner. Никакие установщики не запускаются в реальных пользовательских профилях. Тестовые пакеты создаются локально из искусственных байтов, не считаются настоящим Obscura Worker.

**Граница доказательств:** перед реальным выпуском требуется native-сборка patched Obscura, закреплённые archive/binary SHA-256, проверка origin-gate, настоящий readback и сквозное использование через Agent 0.3. Ни `STAGED`, ни `INSTALLED_NOT_CONNECTED` не означают `READY/CONNECTED/EXECUTED`. Отчёт открытого модуля не подменяет закрытую приёмку Agent.

## Кроссплатформенная проверка и пользовательские отказы

Публичный Actions теперь проверяет шесть сочетаний ОС/архитектуры: Windows x64/ARM64, Linux x64/ARM64, macOS Intel/Apple Silicon. Вначале это **кандидаты на поддержку**, а не подтверждённый выпуск. Каждая нативная платформа получает собственные archive SHA-256, binary SHA-256 и результат установки. Один бинарник нельзя переносить между платформами.

Негативные сценарии: неправильное или отсутствующее согласие хозяина, неправильный digest плана, несовместимый архив, отсутствующий staged-файл, вложенные staging/install каталоги, симлинки, отказ записи, испорченный или удалённый бинарник, установка второй версии и повреждение обновления без потери старой, повторный вызов и readback после повторного создания backend. Все файловые операции выполняются исключительно в disposable каталогах CI, без системной установки.

Ограничения: проверки CI ещё не доказывают работу на всех конфигурациях пользователя, цифровую подпись/нотаризацию macOS, SmartScreen Windows, установку в защищённые системные каталоги, работу через корпоративный прокси или полный маршрут подключения провайдера. Эти внешние ограничения не маскируются зелёным тестовым итогом. Обнаруженные дефекты устраняются до утверждения переносимости.

**Исправление несовместимой архитектуры:** подготовка архива другой платформы допустима как операция с данными, но `apply`, `verify` и `recover` запрещают объявлять его установленным в текущей ОС. Несовпадение ОС или CPU возвращает `INSTALL_PLATFORM_MISMATCH`, неизвестная архитектура — `INSTALL_PLATFORM_UNSUPPORTED`. Проверяется реальная архитектура процесса на runner; успешное копирование байтов не заменяет проверку совместимости программы.

**Проверка права исполнения (POSIX):** совпадение SHA-256 недостаточно, если пользователь или файловая система сняли права запуска. На Linux/macOS `verify/recover` возвращают `INSTALL_NOT_EXECUTABLE` и `installed=false`, не пытаясь молча переустанавливать файл. После восстановления права исполнения повторный readback должен обнаружить исходную проверенную версию. На Windows эта POSIX-проверка не применяется.

## Удаление установленной программы

Универсальный backend также поддерживает `remove(spec, ApprovedRemoval)` для **одной конкретной версии** Obscura. Продукт, использующий модуль, обязан заранее получить явное согласие пользователя, остановить запущенный Worker, зафиксировать собственную квитанцию и сериализовать операции. `ApprovedRemoval` не создаёт отдельной системы разрешений.

Удаление не затрагивает другие версии, подготовленные файлы, корень программ, пользовательские данные и записи приложения. При отсутствии указанной версии возвращается `NOT_INSTALLED` (повторный вызов безопасен). Повреждённый бинарник и пустой каталог после прерванной установки удаляются только по точному пути версии. Если обнаружены посторонние файлы, симлинки, несовпадающие параметры, блокировка ОС или файловая ошибка, операция останавливается с конкретным кодом ошибки; рекурсивное удаление и автоматический повтор запрещены.

После удаления результат проверяется повторным `verify/recover`. Реальная нативная проверка удаляет сначала повреждённое обновление, сохраняя старую рабочую версию, а затем — остановленный Worker. Полный пользовательский сценарий с живыми процессами требует отдельной приёмки приложения-хозяина; нельзя считать закрытый Agent 0.3 проверенным по открытому модулю.

**Маркер принадлежности версии:** новая управляемая установка создаёт рядом с бинарником небольшой `.iwxa-installed.json` со схемой, ID программы и отпечатком закреплённого манифеста. Он нужен только для безопасного определения границ удаления, не является квитанцией или новым реестром. При повреждении маркера удаление отклоняется с `REMOVE_OWNERSHIP_UNKNOWN`; если маркера нет (старый формат), удаление разрешено лишь при совпадении SHA-256 бинарника с закреплённым манифестом либо при полностью пустом каталоге незавершённой установки. Таким образом, неизвестный повреждённый файл не удаляется по одному совпадению пути. Полноценная защита от стороннего процесса с правом изменения каталога не заявляется.

**Порядок записи при установке:** маркер управляемой версии записывается и синхронизируется **до начала копирования** бинарника. Поэтому даже аварийно прерванное копирование оставляет распознаваемую незавершённую IWXA-установку; после отдельного подтверждения её можно удалить. Пустой/неполный файл без маркера и без подтверждённого SHA-256 считается чужим и не удаляется. Риск краша между созданием пустого каталога и записью маркера закрывается удалением только пустого каталога; никакие чужие файлы не затрагиваются.

## Сетевые установки: прогресс, отмена, прокси, диагностика

Публичный backend `prepare` принимает `on_progress(received_bytes, total_bytes_or_none)` и `is_cancelled()`. При сетевой загрузке прогресс отображает фактически полученные байты; полный размер может быть неизвестен. Отмена возвращает `ARTIFACT_DOWNLOAD_CANCELLED` и очищает временный архив; установка не начинается без отдельного `apply`. Для локального архива по завершении подготовки выдаётся `on_progress(1,1)`.

Загрузка из закреплённого GitHub Release теперь учитывает обычные системные/корпоративные настройки HTTPS-прокси (в отличие от изолированного окружения запуска Worker), не отключает TLS-проверку, ограничения редиректов и SHA-256. Причины отказа различаются: `ARTIFACT_DOWNLOAD_NOT_FOUND` (404), `ARTIFACT_DOWNLOAD_ACCESS_DENIED` (401/403), `ARTIFACT_DOWNLOAD_HTTP_FAILED`, `ARTIFACT_DOWNLOAD_TIMEOUT`, `ARTIFACT_DOWNLOAD_TLS_FAILED`, `ARTIFACT_DOWNLOAD_TOO_LARGE`, `ARTIFACT_DOWNLOAD_FAILED`. Автоматических повторов нет — решение остаётся у приложения-хозяина. Эти сценарии проверены изолированными сетевыми фикстурами, а не опубликованным живым релизом.

## Квалификация сетевой установки настоящего Worker (публичный тестовый prerelease)

Отдельный публичный workflow `universal-install-public-https.yml` готовит **только тестовый prerelease** из шести уже проверенных нативных GitHub Actions артефактов **одного закреплённого SHA**. Он проверяет успешность исходного запуска, происхождение каждого бинарника, SHA-256, реальный native handshake и состав отдельного архива каждой ОС. Никакая частная сборка Agent, графический IWXA Browser или неподтверждённый бинарник не публикуются. Упаковка запускает собственные отрицательные тесты; лицензия Apache-2.0 Obscura включается в тестовый prerelease. Тег `iwxa-obscura-native-ci-2026-11-04-test1` обозначает исключительно лабораторный набор, **не продуктовый выпуск для людей**.

Затем шесть GitHub-hosted runner повторно скачивают `manifest.test-only.json` и закреплённый ZIP/tar.gz через **реальный публичный HTTPS GitHub Release**, вызывают `prepare → apply → verify → запуск/handshake → remove → recover` в изолированных временных каталогах. Отчёт содержит имя платформы, контрольные суммы, количество скачанных байтов и доказательство удаления. Финальный PASS выдаётся лишь по получении успешных результатов всех шести runner; создание prerelease само по себе не считается успехом установки. Если GitHub отклонит публикацию или загрузку, фиксируется FAIL, а не подмена локальной фикстурой.
